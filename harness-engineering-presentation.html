Definition

What Is a Harness?

"A prompt file is not a harness."

— Lecture 02, Learn Harness Engineering
1
Everything outside the model weights. Tools, instructions, environment, state, feedback — all of it.
2
Anthropic's Claude Agent SDK is explicitly called "a general-purpose agent harness."
3
OpenAI's core engineer job: design environments, express intent, build feedback loops.
4
The harness determines how much of the model's capability actually gets realized.
The Core Analogy

The New Engineer Problem

👤

New Human Engineer

  • No README, no comments, buried CI
  • Spends most time figuring out, not solving
  • Can at least ask a colleague
🤖

AI Agent — Same Problem, Worse

  • Can only see files you put in front of it
  • Can only run commands you give it
  • No colleague to ask

"The repo IS the spec — all necessary context must live in the repository."

— OpenAI, Harness Engineering

Anything the agent cannot see, for all practical purposes, does not exist.

— Lecture 02
💡

The Implication

The smarter the model, the less you can blame capability — it's always the harness.

Subsystems 1 & 2

Instructions & State

Subsystem 1

📋 Instructions

Create AGENTS.md / CLAUDE.md with:

  • Project overview and purpose
  • Tech stack and pinned versions
  • First-run commands
  • Non-negotiable hard constraints
  • Links to deeper docs (keep it ~100 lines)

"Give a map, not a manual."

— OpenAI
Subsystem 2

📊 State

Long tasks require progress tracking. Use a simple PROGRESS.md:

# PROGRESS.md ## Done - Auth module ✓ - Database schema ✓ ## In Progress - API endpoints (60%) ## Blocked - OAuth callback needs env var

Update before each session ends. Read when the next session starts.

Subsystems 3 & 4

Tools & Environment

Subsystem 3

🔧 Tools

  • Do not disable shell "for security" — if it can't run pip install, it can't work
  • Follow principle of least privilege
  • File access · shell · test runners · linters

Constrain, don't micromanage. Use executable rules to enforce invariants rather than listing instructions one by one.

Subsystem 4

🌐 Environment

Make state self-describing:

# Lock dependencies pyproject.toml / package.json # Specify runtime versions .nvmrc → node 20.x .python-version → 3.12 # Make it reproducible devcontainer.json docker-compose.yml

An agent that can't reproduce your environment will produce unreproducible results.

Subsystem 5 — Highest ROI

Feedback ↑ Highest ROI

Anthropic found that agents confidently praise their own work. The solution: separate "the person who does the work" from "the person who checks the work."

Explicitly declare verification commands in your AGENTS.md:

## Verification Commands # Run before every commit Tests: pytest tests/ -x Type check: mypy src/ --strict Lint: ruff check src/ Full suite: make check # includes all above # The agent MUST run these and see green before declaring done
✅

Closes the loop

Agent verifies its own output objectively

🔁

Enables iteration

Agent can self-correct without human intervention

📈

Lowest investment

A few lines in AGENTS.md → massive quality gains

Case Study

20% → 100% Without Changing the Model

TypeScript + React frontend, ~20,000 lines of code, GPT-4o throughout. Four harness iterations:

Stage 1
20%
Only basic README. Wrong package manager, naming violations, no test run.
Stage 2
60%
Added AGENTS.md with stack versions + naming conventions. Environment issues remain.
Stage 3
80%
Listed verification commands: yarn test && yarn lint && yarn build.
Stage 4
95–100%
Progress file templates for tracking completed / incomplete work each run.

"Four iterations, the model did not change at all, and success rate went from 20% to near 100%. What changed was the harness."

Engineering Discipline

Quantifying Harness Components

Controlled Variable Exclusion Test

  • Fix the model, the task, and all other variables
  • Remove one subsystem at a time
  • Measure performance drop per removal
  • Largest drop = highest marginal contribution

What Anthropic Found

As models get stronger, some components stop being critical — but new critical components always emerge.

Ablation ≠ Root Cause

To find the real bottleneck, you must examine failure records:

  • Was the task unclear?
  • Was context insufficient?
  • Was the environment unreproducible?
  • Was verification feedback missing?
  • Was state management broken?

Ablation results are supporting evidence — not a diagnosis.

"Components with near-zero impact should not be dismissed — they may be redundant, poorly designed, or simply not exercised by the current task."

Design Principles

Rules for Good Harnesses

Principle 1

Give a Map, Not a Manual

~100 lines in AGENTS.md. If it doesn't fit, create a docs/ directory and let the agent read on demand.

Principle 2

Constrain, Don't Micromanage

Use executable rules to enforce invariants. Avoid enumerating instructions one by one — they'll be missed.

Principle 3

Separate Doer from Checker

Agents praise their own work. Build feedback loops where verification is separate from generation.

Principle 4

Harness Rots Like Code

Audit regularly. Pay down harness debt just like technical debt. An outdated AGENTS.md is worse than none.

Summary

Key Takeaways

1
Harness = Instructions + Tools + Environment + State + Feedback. All five subsystems are essential.
2
If it's not model weights, it's harness. Your harness determines how much of the model's capability gets realized.
3
Feedback has the lowest investment and highest return. Get your verification commands right first.
4
Use controlled variable exclusion tests to quantify marginal contribution. Use failure records to find the bottleneck.
5
Harness rots like code. Audit regularly and treat harness improvements as first-class engineering work.
Exercises

Apply It Today

🔎
Exercise 1

Five-Tuple Audit

Score each of your five subsystems 1–5. Find the lowest scorer, spend 30 min improving it, observe the change.

🧪
Exercise 2

Ablation Test

Fix one model and one hard task. Remove subsystems one at a time, measure drops. Then find failures and attribute root causes.

🌉
Exercise 3

Affordance Analysis

Find where the agent "wants to do something but can't." Diagnose: Gulf of Execution or Gulf of Evaluation? Then bridge it.
